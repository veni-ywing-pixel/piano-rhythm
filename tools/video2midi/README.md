# video2midi — 動画から MIDI を作る

「鍵盤＋ノーツが降ってくる」動画（Synthesia 風）から、ピアノリズムで遊べる MIDI ファイルを作る PC 用のツールです。押された鍵盤の色から右手・左手も分けます。

> 入力には **自分で用意した動画ファイル** を使ってください。YouTube からのダウンロード機能はありません（YouTube の規約のため）。動画のアレンジは作者の著作物なので、変換した MIDI は個人で練習する範囲にとどめ、リポジトリにも入れないでください（`.gitignore` で `*.mid` と `*.mp4` を除外しています）。作者が MIDI を配布しているなら、そちらを使うのが確実です。

## 準備（最初の1回）

リポジトリのフォルダ（`index.html` がある場所）で実行します。

```bash
python3 -m venv .venv && source .venv/bin/activate     # ゲームのテストと同じ環境でよい
pip install -r tools/video2midi/requirements.txt
```

`ffmpeg` は必須ではありません（テスト用の動画を H.264 で書き出すときだけ使います。https://ffmpeg.org から入れる）。

## 使い方

### 1. 位置合わせを確認する

```bash
python tools/video2midi/video2midi.py 動画.mp4 --check check.png
```

鍵盤の位置と音域を自動で見つけて、確認用の画像を書き出します。画像を開いて次を確かめてください。

- 黄色の枠が鍵盤を囲んでいる
- 青い枠が黒鍵に重なっている、C の上に出る音名（C4 など）が正しい
- 赤い四角（色を取る場所）が鍵の中に収まっている

ずれていたら、次の引数で直します。

| 引数 | 意味 | 例 |
|---|---|---|
| `--range 低-高` | 鍵盤の音域（両端は白鍵） | `--range A0-C8`（88鍵）、`--range C2-C7`（61鍵） |
| `--region 左,上,右,下` | 鍵盤の位置（ピクセル） | `--region 0,880,1920,1080` |
| `--black-bottom Y` | 黒鍵の下端の y | `--black-bottom 1000` |
| `--start 秒` `--end 秒` | 処理する区間。題名の画面やフェードアウトは keys 方式なら自動で読み飛ばすので、たいていは不要 | `--start 5 --end 182` |

音域は黒鍵の並びから推定します。88鍵（白鍵 52 本）なら A0〜C8 と確定しますが、それ以外は「真ん中がレ（D4）付近」と仮定しているので、オクターブがずれていたら `--range` で指定してください。

### 2. 変換する

```bash
python tools/video2midi/video2midi.py 動画.mp4 -o 曲.mid
```

終わると、パートごとの音の数と色を表示します。できた `曲.mid` をゲームの「MIDIファイル（.mid）を開く」で読み込めば遊べます（タブレットへはクラウドドライブや USB でコピーする）。

### 方式の選び方

| 方式 | 使う場面 | しくみ | 開始時刻の精度（テスト） |
|---|---|---|---|
| `--mode keys`（既定） | 押した鍵盤が光る動画 | 各鍵の色が「押されていない色」からどれだけ変わったかで判定。白鍵は黒鍵より下の部分、黒鍵は黒鍵の部分を見る | ±半フレーム（30fps で平均 9ms） |
| `--mode bars` | 鍵盤が光らない動画 | 鍵盤の少し上の帯で、降ってくるバーの下端（音の始まり）と上端（音の終わり）を何フレームも追う | 平均 1〜2ms |

どちらも、押されたときの色を k-means で分けてパートにします。2色に分かれていれば高い音のほうが「右手」、1色なら「ピアノ」の1パートです。

### そのほかの引数

| 引数 | 既定 | 意味 |
|---|---|---|
| `--parts N` | `auto` | パートの数。3色以上の動画では `--parts 3` など |
| `--threshold 入,切` | `25,15` | keys：押鍵とみなす色差（CIELAB の ΔE）。鍵の色の変化が淡い動画では下げる |
| `--min-dur 秒` | `0.05` | これより短い音は捨てる |
| `--plateau 割合` | `0.6` | keys：押している間の明るさに対してこの割合より弱まったら離したとみなす。離したあと光が薄れて消える動画で、音の終わりが伸びたり連打がつながったりするのを防ぐ。`0` で無効 |
| `--band 上,下` | 自動 | bars：バーを見る帯の y の範囲。`--check` と一緒に指定すると水色の枠で確認できる |
| `--pps N` | 自動 | bars：バーの落ちる速さ（px/秒） |
| `--keep-time` | なし | 動画の時刻のまま出力する（既定は最初の音を 1 秒にそろえる） |

テンポは 120 固定で書き出します（ゲームは秒で扱うので問題ありません）。

## できないこと・苦手なこと

- **間を空けずに同じ鍵を続けて弾く連打**：鍵盤がずっと光ったまま、バーもつながったままの動画では1つの長い音になります。手が替わって色が変わる場合は分けられます
- 鍵盤が画面の端で切れている、斜めに映っている、実写のピアノ：未対応（`--region` と `--range` で合わせられる範囲なら動く可能性はあります）
- 鍵盤の上に重なる大きな光のエフェクト：黒鍵の誤検出が出ることがあります。`--threshold` を上げるか `--min-dur` を長くしてください
- bars 方式は、バーに模様（炎や煙のような質感）や光の粒のエフェクトがある動画では、模様の切れ目をバーの端と誤認して余分な音を大量に出します。鍵盤が光る動画なら keys 方式を使ってください

## 実際の動画での確認

チュートリアル動画 1本（640x360・30fps・88鍵・約1分30秒。鍵盤の上に光の粒のエフェクト、バーに模様、離したあと鍵の光が薄れて消える）で試した結果です。正解の MIDI がないため、仕組みの違う keys 方式と bars 方式の結果の一致と、フレームの目視で確かめました。

- 鍵盤の位置と音域（A0〜C8）は自動で正しく検出。題名の画面とフェードアウトも自動で読み飛ばした
- keys 方式：381音（右手 173・左手 208）。bars 方式の結果と 381音中 380音で一致（開始時刻の差は 95% が 18ms 以内）。残る 1音はフレームを見て keys 方式が正しいことを確認
- 光った鍵の色差は最低でも ΔE 70 で、しきい値（25）に対して十分な余裕がある。しきい値に届かなかった弱い色の変化は、隣の鍵の光のにじみだけだった
- この動画で見つかった「離したあと光が薄れて消える」表現への対策（`--plateau`）と、「鍵盤が映っていない区間の読み飛ばし」を入れ、検証用の描画とテストにも加えた

## 精度の確かめ方（開発用）

```bash
python tools/video2midi/test_video2midi.py           # 約3〜4分。QUICK=1 で重いケースを省く（約2〜3分）
```

テストの流れ：`make_test_song.py` で練習曲を作る → `render_demo.py` で動画を描く → 変換する → `evaluate.py` で元の MIDI と比べる。動画と変換結果は `tools/video2midi/out/` に残ります。

| ケース | 内容 | 結果 |
|---|---|---|
| keys_720p | 1280x720・30fps・60鍵（音域は自動） | 197/197 音一致、開始時刻の誤差は 95% が 15.6ms 以内、左右 100% |
| keys_360p_61 | 640x360・61鍵・やや強い圧縮 | 197/197、15.6ms、100% |
| keys_1080p60_88_noisy | 1920x1080・60fps・88鍵・ノイズ＋強い圧縮 | 90/90、8.3ms、100% |
| keys_alt_style / bars_alt_style | わざと違えた見た目（黒鍵が等間隔、赤いフェルト、左右の余白、灰色の背景、バーの縁取り） | どちらも 197/197、左右 100% |
| bars_nolight | 鍵盤が光らない動画をバー方式で | 197/197、5.2ms、100% |
| same_color | 両手が同じ色 | 197/197、1パート（ピアノ）になる |
| handoff | 同じ鍵を右手→左手と間なしで弾く | 色の変化で2音に分かれる |
| held_key | 曲の大半で押されたままの鍵 | 押されていない色を取り違えない |
| keys_fade | 離したあと鍵の光が 0.15 秒かけて薄れて消える | 197/197、連打もつながらず、音の終わりも伸びない |
| title_fadeout | 最初に題名の画面、最後にフェードアウト | 範囲を指定しなくても 197/197 |

自分で試すとき：

```bash
python tools/video2midi/make_test_song.py song.mid --seed 5 --bpm 110
python tools/video2midi/render_demo.py song.mid -o demo.mp4 --style alt --fps 60
python tools/video2midi/video2midi.py demo.mp4 -o out.mid
python tools/video2midi/evaluate.py song.mid out.mid
```

## ファイル

| ファイル | 内容 |
|---|---|
| `video2midi.py` | 変換の本体（コマンド） |
| `keyboard.py` | 鍵盤の配置（index.html の `R.layout` と同じ式）と自動検出、確認画像 |
| `midi_util.py` | MIDI の読み書き（秒単位のノート列 ↔ SMF） |
| `render_demo.py` | MIDI から検証用の動画を描く（`--style game` はゲームと同じ見た目、`alt` は違えた見た目） |
| `make_test_song.py` | 検証用の練習曲を作る（乱数。著作権の問題がない） |
| `evaluate.py` | 元の MIDI と変換結果を比べる |
| `test_video2midi.py` | 上をつないだテスト |

既存の OSS（video2midi、SynToMid など）のコードは使っていません。
